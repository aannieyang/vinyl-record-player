Simple ADC-master passthrough
============================

adc-dac-passthrough.c continuously reads PCM1808 left/right words, keeps the
left channel, divides it by VOLUME_DIVISOR (8 by default), and sends the result
to both PCM5102A channels. No RIAA, tone table, CSV snapshots or DSP filters.
Set VOLUME_DIVISOR to 1 for unity digital gain; start with low amplifier volume.
Division rounds toward zero (the former Q8 shift rounded negatives downward).
The difference is at most one output PCM24 count.

Wiring
------
Signal                       Pico physical pin    GPIO
ADC BCK + DAC BCK             21                   GP16 (input)
ADC LRCK + DAC LCK            22                   GP17 (input)
ADC DOUT                     24                   GP18 (input)
DAC DIN                      25                   GP19 (output)
ADC SCKI/MCLK                27                   GP21 (output)
DAC SCK                      Ground
All circuit grounds must be connected.

ADC MD1=MD0=HIGH selects master mode with MCLK=256*fs. FMT=LOW selects I2S.
Pico supplies 12 MHz MCLK; ADC supplies 3 MHz BCK and 46,875 Hz LRCK.
The Pico does not drive either BCK or LRCK. The PIO WAIT GPIO operands are
fixed to GP16/GP17, with compile-time checks for matching C definitions.

Why two cores remain
--------------------
Core 1 runs only the continuous read-two/write-two audio loop. Core 0 prints
Left: +/-x.xxx V every 500 ms, like the standalone ADC test. One atomic word
shares the latest left sample; there are no sample arrays or snapshot protocol.
If no new sample arrived, core 0 reports No sample received; check BCK and LRCK.
The printed voltage is the ADC input signal estimate before digital attenuation,
not RMS or the physical input pin's DC bias. USB printing and sleeping never
occur in the audio loop. Unlike ADCTesting.c, reception is never intentionally
stopped between readings. Unlike swg.c, the transmitted data comes from the ADC.

PIO and limitations
-------------------
i2s_duplex.pio is unchanged by this simplification. It follows the ADC clocks,
synchronizes to the left boundary each frame, and transfers 32-bit channel
slots. Bits 30..7 hold the signed PCM24 sample; other transmitted bits are zero.
The four-word initial TX prefill provides two silent frames.

This remains CPU-serviced audio without DMA. FIFO stalls can corrupt/drop
samples because the ADC clocks continue independently. Detailed FIFO diagnostics
are no longer printed. Simplifying the code is not a demonstrated noise fix;
the earlier noise was also present with tone and silence data.

Build and validation
--------------------
Use the existing Pico VS Code/CMake build. AUDIO_MODE and DEBUG_STATUS options
have been removed; the project now always builds passthrough with voltage output.
Old cached values have no effect. plot_adc.py expects CSV and is not compatible
with this voltage-only output. The independent ADC/DAC test projects are intact.

bench-test/passthrough-status.uf2 is rebuilt from the simplified source.
The older tone/silence UF2 files remain historical diagnostic artifacts and
are not generated by this source. See bench-test/WIRING.txt before using them.

Run python3 adc-dac-passthrough/tests/verify_audio.py for the external-clock PIO
simulation and C conversion/gain checks. These and an SDK 2.3.1 Pico 2 W build
pass. No new hardware playback verification has been performed.
